# entra-emulator v0.5.0

The release that makes **browser** apps work. Until now the emulator sent no
CORS headers at all, so MSAL.js could not fetch discovery, the JWKS or the token
endpoint from a single-page app's own origin — every request was blocked by the
same-origin policy, and no browser SPA could authenticate against the emulator.
Server-side clients were unaffected, which is exactly why it went unnoticed: the
five SDK suites in CI all run outside a browser.

Alongside that, four Graph surfaces land, each wired into behaviour rather than
stored and forgotten.

## Browser support (the headline)

- **CORS on the OIDC surface.** Discovery, JWKS and instance discovery reflect
  the caller's `Origin` and `Vary` on it; preflight answers with the telemetry
  headers MSAL.js actually sends (`x-client-SKU`, `client-request-id`, …), which
  matters because Go's `ServeMux` matches on method and a POST-only route would
  otherwise `405` the preflight before the real request happened.
- **The token endpoint is gated as Entra gates it** — CORS only for an origin
  registered as a redirect URI of type `spa`. Being *more* permissive would have
  been worse than useless: an app would work locally and then fail against real
  Entra with precisely the error this emulator exists to surface early.
- **A new CI witness.** `@azure/msal-browser` now drives the emulator through
  the authorization-code + PKCE redirect flow in a real headless Chromium, on
  every push. It is what found the CORS gap on its first run.

## Graph

- **`federatedIdentityCredentials` on applications.** Workload identity
  federation was manageable only over the admin API; the Graph resource real
  clients use now exists, writing the same rows the token endpoint matches — so
  a trust created over Graph immediately authenticates an external workload,
  and `PATCH`ing its subject changes who can.
- **Token lifetime policies.** `policies/tokenLifetimePolicies` plus the `$ref`
  assignment onto an application, parsed from Entra's own encoding (settings
  live in a JSON *string*, with .NET `[d.]hh:mm:ss` durations). An assigned
  policy — or `isOrganizationDefault` — changes the `exp` of the tokens actually
  minted. A definition that would set nothing is refused rather than stored,
  because silently inert is worse than rejected.
- **Directory audit logs.** `auditLogs/directoryAudits` over a real mutation
  journal: every change through the Graph write surface records its activity,
  category, target resource, and the caller it is attributed to. An app-only
  caller reports no user, which is correct rather than missing.

## Fixes

- Two CodeQL findings, both in code added during this cycle: the directory
  recorder no longer sizes an allocation from a request's `$top`, and the
  browser e2e harness trusts the emulator's certificate as a CA instead of
  switching certificate validation off process-wide.
- The Python e2e runner locates virtualenv executables on Windows.

## Upgrading

Nothing to do, and nothing to re-read. No endpoint changed shape, no seed data
moved, and every id is unchanged from v0.4.x.

One behaviour is genuinely new rather than altered: browser apps can now
authenticate. If you have a single-page app, register its origin as a redirect
URI of type **`spa`** — the same registration real Entra requires — or the token
endpoint will not grant it CORS.
