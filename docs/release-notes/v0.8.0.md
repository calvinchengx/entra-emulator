# entra-emulator v0.8.0

The release that grew FederationMetadata. v0.6.0 added SAML 2.0
SP-initiated SSO. This one adds the other protocol that same document
already had to speak: WS-Federation passive sign-in.

The ledger moves: **54 green / 17 not implemented → 55 / 16**. Independently
evidenced **48/54 (89%) → 49/55 (89%)**. Emulated 5 and bring-your-own-engine 3
are unchanged.

## WS-Federation passive sign-in

An existing ASP.NET relying party points `MetadataAddress` and `Wtrealm` at
the emulator. The **existing** FederationMetadata URL grows a WS-Fed
`RoleDescriptor` (`xsi:type=fed:SecurityTokenServiceType`): both
`PassiveRequestorEndpoint` and `SecurityTokenServiceEndpoint` are
`/{tid}/wsfed`, and the signing cert is the same one `IDPSSODescriptor`
already publishes.

`GET|POST /{tid}/wsfed` answers `wa=wsignin1.0`. Unauthenticated, that is
the same account picker OIDC and SAML already use (signed Kind `"wsfed"`),
not a second login UI. After pick, the browser POSTs `wa=wsignin1.0` plus a
SAML **2.0** `wresult` (RSTR) to a registered **`wsfed-reply`**. Audience is
`wtrealm`; Issuer is the metadata entityID; NameID is persistent.

Unmodified `Microsoft.AspNetCore.Authentication.WsFederation` 8.0.19
completes that path (`python3 e2e/run.py wsfed`). That is the stranger, not
an extension of `e2e/dotnet`.

The exchange is audited as flow `wsfed`. `ClientID` is `wtrealm`. The RSTR
is never written to the audit event.

## Refusals that stay on the emulator

Unknown or empty `wtrealm`; missing, unregistered, `saml-acs`, `web`, or
cross-app `wreply`; unsolicited `wresult` (no signed Kind from this STS).
Those errors render here. They are not redirected to a URL the caller named.

## Out of this cut

SOAP / active WS-Trust, `/common/wsfed`, SAML 1.1 inside `wresult`,
witnessed `wsignout1.0` (sign-out is advertised on
`PassiveRequestorEndpoint` only), IdP-initiated login, encryption, MFA/CA.

## Upgrading

Nothing existing breaks. Seed ids, OIDC, and SAML are unchanged. Two things
are new for a WS-Fed RP:

- Register the reply URL as type **`wsfed-reply`**. Type-blind
  `HasRedirectURI` would accept a `saml-acs` or OIDC `web` URI, which is a
  different POST contract.
- FederationMetadata is larger: it still has `IDPSSODescriptor`, plus the
  WS-Fed `RoleDescriptor`. SAML SPs that already consumed this URL keep
  working.
