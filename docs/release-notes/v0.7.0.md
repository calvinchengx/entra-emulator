# entra-emulator v0.7.0

The release that asked Entra, and then asked strangers. v0.6.0 proved
green rows with real clients. This one does two things that work still
could not: capture live Entra token envelopes and compare them, and put
a packaged Microsoft CLI — not another of our SDK suites — on a row that
was still `go:`.

Independently-evidenced parity went from **43/54 (80%) to 48/54 (89%)**.
The ledger is unchanged: 54 green, 5 emulated, 17 not implemented.

## The first Entra token diffs

A capture tenant (`entraemulatordiff.onmicrosoft.com`) records real Entra
`/token` envelopes. The emulator now matches those envelopes on the paths
that were wrong:

- Unknown resource: Entra answers `invalid_resource` / AADSTS500011 / 400.
  The emulator was `invalid_scope` / 70011.
- Unknown client: Entra answers `unauthorized_client` / AADSTS700038 / 400.
  The emulator was `invalid_client` / 700016 / 401.
- Bad secret: Entra's 401 carries `error_uri` and a Trace ID suffix.
- Client-credentials success: Entra omits `scope`. The emulator always sent it.

A structural JWT compare then checks what a client actually consumes — `alg` /
`typ`, `kid`, `ver: "2.0"`, `tid` / `azp`, issuer path, protocol claim names —
and names the Entra extras we do not mint (`aio`, `rh`, `uti`, …). Exact JWT
match is rejected on purpose: that would be a fingerprint, not a contract.

## Strangers on already-green rows

Four claims were 🟢 on our own Go tests. They now have a CI job driving
something that is not us:

- **Passkeys.** Chromium + CDP virtual authenticator registers and asserts on
  the emulator origin; the ID token carries `amr: ["fido"]`. msal-browser
  cannot do this — WebAuthn pins RP to page origin, and the SPA is a
  different origin.
- **Implicit / hybrid.** Chromium drives `response_type=id_token` and
  `code id_token`. msal-browser never emits those.
- **Fabric-audience tokens and workspace identity.** fabric-emulator's own
  handshake tests, against this checkout, over HTTP.
- **Azure CLI.** Unmodified `az cloud register` + `az login --service-principal`,
  then `az account get-access-token` for Graph and ARM. The CLI verifies TLS.
  That is what moved the wildcard-cert row off the own-only list.

Wilson (`Microsoft.IdentityModel`) was already validating tokens inside
`sdk-e2e`. It is named on the witness table now, and trusts the emulator leaf
instead of every certificate.

## Upgrading

Nothing to do. No endpoint changed shape, no seed data moved, and every id is
unchanged from v0.6.0. Error envelopes for unknown resource, unknown client,
and bad secret are closer to Entra; a client that branched on the emulator's
old codes should follow Entra's.
