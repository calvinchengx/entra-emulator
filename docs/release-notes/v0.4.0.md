# entra-emulator v0.4.0

The seed data grows up, and the tenant changes: every placeholder GUID is now a
realistic, fixed v4 GUID. That is a **breaking change** for anything that names
the old IDs — which is most of the family — so read the migration first. Around
it, this release adds workload identity federation, five new Graph surfaces,
and a set of OIDC capabilities real clients ask for.

## Breaking: realistic opaque GUIDs (`feat(seed)!`)

Patterned placeholders (`11111111-…`, `aaaaaaaa-…`, `cccccccc-…`) never matched
what real Entra issues, and a uniform GUID is a weak test oracle — it survives
segment transposition and most mis-slicing, so parsing bugs pass unnoticed.
The seeds are still **fixed and deterministic**; only the values changed.

| Entity | Old | New |
|---|---|---|
| Tenant | `11111111-1111-1111-1111-111111111111` | `6f89cf12-978b-4d23-ac18-9ef0c127cf87` |
| User Alice | `aaaaaaaa-0000-…-0001` | `df8ec5dd-1599-45ef-908b-4ae020cd1dbe` |
| User Bob | `aaaaaaaa-0000-…-0002` | `0d4ba1f9-cab1-4200-b516-d4cb8b340930` |
| Group Engineering | `bbbbbbbb-0000-…-0001` | `54a9d08c-889d-489e-b534-336fe19dbfce` |
| App: Sample SPA | `cccccccc-0000-…-0001` | `189c7070-78a3-4c13-aa18-20a2ca5755ca` |
| App: Sample Daemon | `cccccccc-0000-…-0002` | `00d88624-f0d7-46f6-a641-6232c2608928` |

Passwords and secrets are unchanged (`Password1!`, `daemon-app-secret`).

**Migrating:** update every issuer/authority URL embedding the tenant, and
every seeded object ID your tests name. A v0.4.0 emulator serves **404 on the
old tenant's discovery path** — that is the failure signature of a
not-yet-migrated consumer, surfacing as `AADSTS90002: Unknown tenant` in MSAL
and the Azure SDKs. Do not mix: a consumer swept to the new tenant against an
older entra fails the same way in reverse. The family's certified combination
lives in [azure-emulators](https://github.com/calvinchengx/azure-emulators)'
compose defaults; this release is that BOM's entra.

## Identity

- **Workload identity federation** — exchange an external OIDC token for an
  app's token via federated credentials, no client secret.
- **Delegated tokens reach the well-known Azure resources** (carried from
  v0.3.1, now joined by) **implicit and hybrid response types**, so older
  auth-code flows and SPAs of both generations resolve.

## OIDC endpoints

- **JAR by reference** (`request_uri`), SSRF-guarded.
- **Front-channel logout**, scoped to the session's relying parties.
- Discovery now **advertises `private_key_jwt`** and `http_logout_supported`.

## Graph

- **B2B guest invitations** — with the invitation redirect bound server-side
  (fix landed in this release).
- **Administrative units**, **custom security attributes**, and **custom
  (tenant-authored) directory role definitions**.
- **Sign-in logs** over a user-aware audit recorder.
- **Password reset** on the password authentication method.

## CI and docs

- `make up` now checks the **image under test**, not the last release — the
  release gate can no longer pass on stale bits.
- Pages deploys survive PR-build bursts (per-ref concurrency groups).
- The ARM companion and the family's dependency order are documented; the
  family-level compose moved to the neutral `azure-emulators` repo.

## Consumers at release time

azure-keyvault-emulator ≥ `a589156` pins this release in its e2e witnesses;
`azure-emulators` certifies it in the family BOM. arm-emulator and
fabric-emulator still carry pre-0.4.0 references and fail against the new
tenant until bumped — tracked by the family `pins` check.
